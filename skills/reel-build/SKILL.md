# 쇼릴 구현 절차

쇼릴 폴더(`showreel/reels/{slug}/`)의 파일 역할:

| 파일 | 고치는가 | 역할 |
| --- | --- | --- |
| `reel.js` | **고친다** | 테마, 장면 함수, 장면 표, 효과음 큐, 음악 설정 |
| `index.html` | 제목·설명·글꼴 링크만 | 플레이어 페이지 |
| `engine.js`, `music.js` | 고치지 않는다 | 런타임, 음악 합성기 |
| `_work/` | 기록한다 | 스토리보드, 구현 기록, 검토 의견 |
| `build/` | 도구가 만든다 | 미리보기, 검사 결과, 웹 게시용 단일 파일 |

엔진 전체 API는 `references/engine-api.md`, 장면 패턴 코드는 `references/patterns.md`, 완성 예제는 `references/example-showreel-reel.js`(이 플러그인의 작동 방식을 소개하는 30초 쇼릴)에 있다. 처음 구현할 때 예제를 한 번 훑어보면 구조를 가장 빨리 파악할 수 있다.

## 시각 기준

- **전역 시각**: 영상 시작부터의 초. HUD 타임코드, `render.js --times`, `audit` 출력, 효과음 큐가 이 기준이다.
- **로컬 시각**: 장면 함수가 받는 t(장면 시작부터의 초).
- 변환: `전역 = SC[i] + 로컬`. 코드에서는 `const at = (i, lt) => SC[i] + lt`를 쓴다.

## 1. 순서

1. 스토리보드(`_work/01_storyboard.md`)를 읽고 장면 표를 먼저 코드로 옮긴다. `SC = [0, 3.4, 8.0, …, 30]` 같은 경계 배열 하나를 두고, 장면 표·큐·`meta.dur`가 모두 이것을 참조하게 한다(`dur: SC[SC.length - 1]`). 그래야 나중에 장면 길이를 바꿀 때 `SC` 한 곳만 고치면 된다.
2. 팔레트를 `C = {…}` 상수로 만든다. 이름은 주제의 사물로 붙인다(`rack`, `beam`, `tape`처럼). 색을 장면 코드에 직접 쓰지 않는다.
3. 장면을 하나씩 구현하고, 장면 하나를 끝낼 때마다 그 장면의 시각만 미리보기로 확인한다.
   `node showreel/tools/render.js sheet showreel/reels/{slug} --times 4.2,5.8,7.6`
4. 모든 장면을 만들면 효과음 큐와 음악 설정을 채운다.
5. 레이아웃 검사를 돌리고 문제를 고친다.
   `node showreel/tools/render.js audit showreel/reels/{slug}`
6. 전체 미리보기(`sheet`, 인자 없이 장면별 두 컷)로 마무리를 확인하고 `_work/02_build_log.md`를 쓴다.

MP4 렌더링(`video`)은 오케스트레이터가 검토를 통과한 뒤에 한다. 30초에 약 1분, 2분짜리는 약 4분이 걸리므로 구현 중에는 `sheet`와 `audit`만 쓴다. 2분짜리는 `audit`도 1분 안팎 걸린다.

2분짜리(장면 15개 이상)는 막 단위로 나눠 구현한다. 막 하나를 끝낼 때마다 그 막의 `--times` 미리보기와 `audit`을 돌린다. 모든 장면을 다 쓴 뒤 한꺼번에 확인하면 같은 실수가 여러 장면에 퍼진다.

## 2. 장면 함수 규칙

```js
function s2(t, d){          // t: 장면 시작 후 경과 초(와이프 중에는 약간 음수), d: 장면 길이
  gridBg(C.ground, C.joint);            // 1) 배경을 먼저 전부 칠한다
  rise('헤드라인', 160, 400, .1, t, { k:'d', s:100, c:C.ink });   // 2) 요소마다 등장 시각을 t 기준으로
  const p = eoX(P(t, 1.0, 1.3));        // 3) 진행률 = 이징(P(t, 시작, 끝))
  ...
}
```

- 프레임은 t만으로 결정한다. 전역 변수에 상태를 쌓지 않는다. 경로·키프레임처럼 계산이 필요한 것은 파일을 불러올 때 한 번 계산해 상수로 둔다.
- 등장 시각은 장면 시작 기준 0.05초 이후로 잡는다. 와이프가 끝나는 시점(약 0.22초)에 첫 요소가 움직이고 있어야 전환이 살아 보인다.
- 퇴장 애니메이션은 대부분 필요 없다. 다음 장면의 와이프가 덮는다. 장면 안에서 내용을 교체할 때만 퇴장시킨다(예: 질문이 올라가며 사라지고 엔딩 카드가 나옴).
- **장면 = 슬라이드.** 발표 모드는 각 장면의 끝(와이프 시작 0.3초 전, `reel.presenter.holdOf(i)`)에서 멈춘다. 그 시점에 모든 요소가 등장을 마치고 정지해 있어야 한다. 마지막 등장은 장면 끝보다 0.8초 이상 앞서 끝낸다. 깜빡임, 흐르는 줄무늬처럼 계속 움직이는 장식은 괜찮다.
- 흔들림, 확대 같은 카메라 효과는 장면 함수 첫 줄에서 `ctx.translate`로 준다. 엔진이 호출 전후로 save/restore를 한다.

## 3. 레이아웃 규칙 (1920×1080)

- **글자 안전 영역**: x 160–1760, y 120–980. 모서리는 HUD(장면 태그, 시간, 진행 막대)가 쓴다.
- **왼쪽 정렬 기준선**: x = 160. 제목, 본문, 라벨을 같은 기준선에 맞춘다. 가운데 정렬은 엔딩 카드에서만 쓴다.
- **글자 크기 단계**: 디스플레이 150–170 / 90–104 / 84–88, 본문 44 / 34–40 / 28–30, 라벨 모노 20–26, 주석 18. 한 장면에서 세 단계를 넘기지 않는다.
- **폭 예산**: 한글 디스플레이 글꼴 한 글자 ≈ 글자 크기 × 1.0, 공백 ≈ 0.3, 모노 숫자 ≈ 0.6. 긴 문구는 `measure()`로 폭을 재서 다음 요소의 x를 정한다. 추측한 좌표로 붙이면 글꼴이 바뀔 때 겹친다.
- **두 열 배치**: 그림을 왼쪽 60%(x 150–1230), 설명을 오른쪽(x 1320–1800)에 둔다. 오른쪽 열 문구는 한 줄 480px 안에 들어가야 한다(30px 본문 ≈ 15자).
- 겹침이 의도된 요소(도장, 라벨 위 스탬프)는 `overlapOk:true`, 흘러가는 티커와 HUD는 `free:true`, 출처 표기 같은 잔글씨는 `skim:true`를 준다. 검사 경고를 없애려고 붙이지 않는다. 의도가 맞을 때만 붙인다.

## 4. 색과 대비

- 포화된 바탕(파랑, 빨강) 위에 반투명 강조색을 올리지 않는다. 섞여서 탁한 색이 된다. 강조는 불투명 색으로 칠하고, 크기나 위치(안쪽 여백)로 상태를 나타낸다. (창고 쇼릴에서 피킹한 칸을 반투명 노랑으로 칠했다가 올리브색이 되어 고친 적이 있다.)
- 경고색(빨강)은 한 영상에서 한 가지 의미에만 쓴다(예: 결품, 폐기, 유의하지 않음).
- 어두운 장면과 밝은 장면을 번갈아 배치하면 와이프가 선명해진다. 장면 표의 `dark` 값은 HUD 글자색을 정하므로 배경과 맞춘다.

## 5. 효과음 큐와 음악

큐는 `Reel.define({ cues: () => ({…}) })`에 절대 시각(초)으로 쓴다. 장면 코드와 같은 상수에서 계산한다.

```js
const at = (i, lt) => SC[i] + lt;           // 장면 i의 로컬 시각 → 절대 시각
cues: () => ({
  hits:  [at(2, 1.3 + .4 * .25)],           // stamp()가 P(t, 1.3, 1.55)로 찍히면 착지 ≈ 시작 + 0.4 × 길이
  drops: [at(2, 1.3 + .4 * .25)],           // 큰 한 방 직전 0.3초 정적
  ticks: [[at(1, 1.6), at(1, 2.7)]],         // 카운터가 도는 구간
  keys:  [...QUESTION].map((_, k) => at(6, .15 + (k + 1) / 15)),   // typeOn(cps = 15) 글자마다
  end:   at(6, 2.15)                        // 엔딩 타이틀 등장 순간
})
```

- 장면 전환 효과음과 `chorus` 구간 시작 심벌은 자동으로 들어가니 따로 넣지 않는다.
- 모든 큐 이름과 음악 구간 스타일은 `references/engine-api.md` 「소리」에 있다.
- 2분짜리는 막마다 `scenes[i].music`을 바꾸고, 필요하면 `scenes[i].prog`로 코드 진행도 바꾼다. 같은 편곡이 2분 내내 이어지지 않게 한다.
- `music: { bpm, offset, prog, endChord, endRoot, seed }`. `offset`은 박자 격자의 시작 시각이다. 장면 경계 대부분이 박자에 떨어지게 고른다(150 BPM이면 박자 0.4초, 경계가 x.2초에 많으면 `offset: .2`).

## 6. 확인 도구

| 명령 | 언제 | 보는 것 |
| --- | --- | --- |
| `sheet <dir> --times a,b,c` | 장면 하나를 만들 때마다 | 해당 전역 시각의 프레임(3열, 칸당 640×360) |
| `sheet <dir> --times … --cols 2` | 작은 글씨 확인 | 칸당 960×540 |
| `frames <dir> --times a,b` | 30px 이하 글씨, 세부 확인 | 원본 1920×1080 PNG(`build/frames/`) |
| `sheet <dir>` | 마무리 | 장면별 50%·93% 시점 |
| `sheet <dir> --holds` | 마무리 | 장면별 완성 화면(발표 모드 정지 화면) = 슬라이드 목록 |
| `audit <dir>` | 마무리, 수정 후 | 문제 종류, 전역 시각 구간, 장면 |
| `audio <dir>` | 큐를 바꾼 뒤 | `reel-music.mp3` 생성(약 3초) |
| `--help` | 옵션이 헷갈릴 때 | 전체 사용법 |

`sheet`·`frames` 결과 이미지는 Read 도구로 직접 본다. 검사 결과는 `build/audit.json`에도 남는다.

- `reading-critical`(필요 시간의 절반도 안 보임)은 반드시 고친다. `reading-tight`는 핵심 문장이면 고치고, 장식이면 `skim:true`가 맞는지 판단한다.
- 고치는 순서(영향이 작은 것부터): ① 장면 안에서 등장을 앞당긴다 → ② 스토리보드와 협의해 문구를 줄인다 → ③ `SC`의 경계를 옮기거나 전체 길이를 늘린다. ③을 하면 `at()`로 계산한 큐와 음악(장면 구간을 따라감)은 자동으로 움직인다. `meta.poster`만 따로 확인한다.

## 7. 흔한 실수

- `engine.js`에 쇼릴 전용 코드를 넣음 → 모든 쇼릴 전용 코드는 `reel.js`에 둔다.
- `Math.random()`, `Date.now()` 사용 → 프레임마다 결과가 달라져 MP4와 웹이 어긋난다. `mulberry32(seed)`를 쓴다.
- 카운트업 숫자를 `rise()`로 그림 → 값이 바뀔 때마다 새 문자열이 올라온다. 카운터는 `text()`로 그린다.
- 모노 글꼴로 한글을 씀 → 한글은 본문 글꼴로 대체되어 폭이 달라진다. 폭은 반드시 `measure()`로 잰다.
- 큐 시각을 숫자로 직접 적음 → 장면 경계를 바꾸면 소리가 어긋난다.
- 등장 직후 사라지는 문장 → 검사의 `reading-*` 경고로 잡힌다. 문장보다 장면 길이를 먼저 확보한다.

## 9. 숏동영상 모드 (3~5분, 자막형)

스토리보드 머리에 "숏동영상"이 적혀 있으면 이 절을 따른다. 30초·2분과 달리 파일이 커지고 렌더링이 길다.

### 파일 나누기
5분짜리를 `reel.js` 한 파일에 넣으면 2,000줄이 넘어 고치기 어렵다. 장(챕터)별로 나눈다.

```
reel.js            # 팔레트, 공용 소품 함수, SC, 장면 표, 큐, 음악 — Reel.define은 여기서만
scenes/ch1.js      # 1장 장면 함수들 (function c1s0(t, d){…})
scenes/ch2.js
...
```

- `index.html`의 `<script src="engine.js">`와 `<script src="reel.js">` 사이에 `<script src="scenes/chN.js"></script>`를 장 순서대로 넣는다. 장 파일은 `reel.js`보다 먼저 불러오므로, 팔레트·공용 함수는 `scenes/common.js`(맨 앞)에 두고 `reel.js`에는 `SC`·장면 표·큐·음악만 남겨도 된다.
- `render.js bundle`은 `<script src="….js">`를 모두 한 파일에 넣는다. 경로에 하위 폴더가 있어도 된다.
- 장 사이에 되풀이되는 그림(창고 지도, 흐름도, 주인공 카트)은 `common.js`에 함수로 하나만 만들고 인자(강조할 칸, 색, 진행률)로 상태를 바꾼다. 스토리보드의 "같은 도식 재사용" 원칙을 코드에서도 지킨다.

### 자막
- `captions([[t0, t1, '자막'], …], t)`를 장면 함수 **마지막 줄**에서 부른다(다른 요소 위에 그려지게). 시각은 로컬 시각이다. 스토리보드 비트 표의 시각을 그대로 옮긴다.
- 자막 띠 영역(y 890~985)에는 다른 요소를 두지 않는다. 그림의 아래 끝은 y 860 이하.
- 자막 문장은 audit의 읽기 시간 검사를 받는다(free/skim 금지).
- 한 장면의 자막 목록은 장면 함수 밖 상수(`const CAP_07 = [...]`)로 두고, 효과음 큐도 같은 상수에서 계산한다.

### 전환·장 카드
- 장 안의 장면 전환은 `cut: 'fade'`, 장이 바뀌는 첫 장면(장 카드)만 `cut: 'wipe'`. `theme.cut: 'fade'`로 기본값을 바꾸고 장 카드에만 `cut: 'wipe'`를 적으면 편하다.
- 장 카드는 공용 함수 하나로 만든다(번호, 장 제목, 진행 표시 `2 / 6`).
- 장면이 길어도 `theme.push`(천천히 확대)는 장면 길이에 비례하므로 그대로 둔다. 15초 장면에서 너무 크면 .01로 줄인다.

### 음악
- 템포 90~110 BPM. 설명 구간은 `calm`/`pulse`, 장 카드·반전·결론만 `drive`/`chorus`.
- `music.lufs: -16`을 넣는다. 조용한 구간이 길어 피크 정규화만으로는 음량이 -19 LUFS 안팎으로 작다.
- 연달아 찍히는 효과음(도장 8번 등)은 `{t, g}`로 뒤쪽 음량을 줄인다.
- 장마다 `scenes[i].prog`로 코드 진행을 바꾼다.
- `fade` 전환은 작은 휘익만, `wipe`는 휘익+쿵이 자동으로 들어간다. `cut`은 소리가 없다.

### 확인 순서와 시간
- 장 하나를 끝낼 때마다: 그 장의 `sheet --times`(비트마다 한 컷) → `audit`. 5분짜리 `audit`은 2~3분 걸린다.
- 마무리: `sheet --holds --cols 4`(장면 30개 안팎이 한 장에), `audit` 전체.
- MP4 렌더링은 5분에 약 10분 걸린다. 구현 단계에서는 하지 않는다.
